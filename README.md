# Classnest.mk – PoC

Демо на маркетплејс за работилници и искуства (Next.js + Tailwind). Податоците се примерни, без база и без плаќање.

## Стартување

```bash
npm install
npm run dev
```

Отворете http://localhost:3000.

## Структура

- `src/data/reference.ts` – категории и градови (од `reference.json`)
- `src/data/demo.json` – 12 демо домаќини и понуди, се полнат во базата со `npm run db:seed:demo`
- `src/app/` – страници (почетна, листа, детали, checkout, потврда, домаќин)
- `src/components/` – Header, Footer, ClassCard, SearchForm, BookingWidget, CheckoutForm, HostForm
- Боите се менуваат во `src/app/globals.css` (`@theme`)

## Домаќини: регистрација, најава, фотографии

- `/host` – регистрација (име, е-пошта, лозинка, град, категорија, опис и до 6 фотографии)
- `/host/login` – најава, `/host/dashboard` – профил со фотографии за сопствениот профил и искуства
- **Сметките, сесиите, домаќините, приватните податоци (телефон, датум на раѓање, ЕДБ, банка) и понудите со достапност се во MySQL** (чекори 3, 4 и 6). `.data/db.json` повеќе не се користи. Само фотографиите уште се во `uploads/` (чекор 5, не се комитира).
- Лозинки: scrypt. Сесии: httpOnly cookie, во базата се чува само хеш на токенот.
- **Јавните страници (почетна, листа, детали, домаќини) читаат од MySQL.** Видливи се само понуди со статус `PUBLISHED` на активни домаќини. Ако базата не одговара, страниците покажуваат празна состојба наместо да паднат.
- Демо податоци: `npm run db:seed:demo` (12 домаќини и 12 објавени понуди; сметките немаат лозинка, никој не може да се најави како нив).
- **Админ екран: `/admin/listings`**: одобрување и одбивање на понуди. Види „Администратори“ подолу.
- Резервно, од командна линија: `npm run listing:review` (листа), `npm run listing:review -- publish <slug>`, `... reject <slug>`.
- Фотографии за демо: `npm run seed:photos` (види `seed-photos/README.md`)

## Администратори

Администратор е сметка со улога `ADMIN`. **Улогата не може да се добие преку сајтот**: ниту при регистрација, ниту од друг корисник. Првиот админ се создава од терминал, од некој со пристап до серверот и базата (`DATABASE_URL` во `.env.local`).

**Прв админ (препорачано: посебна сметка само за админ, не личната и не сметка на домаќин):**

```bash
npm run admin:role -- create admin@example.com "Име и презиме"
```

Лозинката се бара во терминалот (скриено, двапати) и никогаш не се пишува во командата. Потоа најавете се на `/host/login`: админ без профил на домаќин оди директно на `/admin/listings`.

**Улога на веќе постоечка сметка** (на пр. колега што се регистрирал на `/host`):

```bash
npm run admin:role -- grant colleague@example.com
npm run admin:role -- revoke colleague@example.com   # одземање
```

- `create` не работи ако е-поштата веќе постои (користете `grant`), а `grant` не создава сметка (користете `create`).
- Секоја промена се запишува во `audit_log` (`admin.create`, `admin.grant`, `admin.revoke`).
- Секој админ екран и API го проверува ADMIN на серверот при секое барање. Останатите гледаат 404.
- Чувајте барем двајца админи. Одземете ја улогата кога некој ќе ја напушти екипата.
- Одобрување на понуди: `/admin/listings` (табови: на чекање, објавени, одбиени, симнати, скриени). Картичката ги прикажува фотографиите. Акции: „Одобри и објави“, „Одбиј“ (од преглед), „Симни“ (од објавена) и „Врати на објавено“ (од симната). Одбивањето и симнувањето бараат причина.
- Домаќинот ја гледа причината на својата понуда. Одбиена понуда што ќе ја уреди оди автоматски пак на преглед. Симната понуда е заклучена: домаќинот не може да ја скрие, прикаже ни врати, само администратор.
- Секоја одлука се запишува во `audit_log` (кој, што, зошто, IP). Резервно од терминал: `npm run listing:review`.

## База на податоци (MySQL + Drizzle)

Дизајн: `docs/backend-design.md`. Чекор 1 е напишан: врска со база, миграции, тестови.

```bash
# .env.local веќе постои (има BANK_DATA_KEY): НЕ го пребришувајте. Само додајте ги DATABASE_URL и DB_POOL_SIZE од .env.example.
npm run db:up                  # локален MySQL во Docker (Docker Desktop мора да работи)
npm run db:migrate             # ги создава табелите (cities, categories, outbox_events, audit_log, idempotency_keys)
npm run db:seed                # ги полни градовите и категориите (безбедно е да се врти повеќепати)
npm run db:import-accounts     # ЕДНАШ: ги префрла постоечките сметки од .data/db.json во MySQL (прави резервна копија)
npm run db:import-hosts        # ЕДНАШ, по db:import-accounts: ги префрла домаќините од .data/db.json во MySQL (прави резервна копија)
npm run db:import-experiences  # ЕДНАШ, по db:import-hosts: ги префрла понудите и достапноста; ги преименува папките со фотографии
npm test                       # unit тестови (54). Со база: види подолу
TEST_DATABASE_URL=mysql://classnest:classnest@127.0.0.1:3306/classnest npm test   # + интеграциски тестови (36)
npm run dev                    # па http://localhost:3000/api/health
```

- `/api/health` враќа `{"status":"ok","database":"up"}` кога базата одговара. Без `DATABASE_URL` пишува `not-configured`.
- Нова табела: ја додавате во `src/server/db/schema/`, па `npm run db:generate` создава SQL во `drizzle/`. Проверете го SQL-от и комитирајте го.
- **Никогаш не менувајте миграција што веќе е извршена.** Додадете нова.
- Во продукција: `npm run db:migrate` се врти на серверот преку SSH пред да почне новата верзија.
- Ако `npm install` пријави грешка `edgesOut`, користете `npm install --legacy-peer-deps` (грешка во npm 10.8 со vitest).
